서로 다른 가능성이 만나, 함께 더 나은 변화를 만드는 배움.

검토 기준일: 2026년 9월 17일 · 제안 범위: 브랜드 전략, 정보 구조, 메인 페이지 데스크톱·모바일 시안, 공통 규칙 및 인터랙션. 시안은 검토용이며 실제 사이트에 배포하지 않았습니다.

## 2. 브랜드 포지셔닝과 핵심 메시지

**포지셔닝 제안:** 개발 기본기와 AI 활용을 미션·리뷰·동료 학습으로 연결하는 소프트웨어 교육 파트너. 개인의 성장과 조직의 현장 적용을 함께 설계합니다.

**브랜드 중심 개념:** 서로 다른 가능성이 만나, 함께 더 나은 변화를 만드는 배움.

전문성은 추상적인 ‘최고’ 수식어보다 교육자가 설계한 문제, 리뷰 기준, 수정 결과로 보여줍니다. 따뜻함은 친근한 그림만으로 표현하지 않고, 현재 수준을 존중하는 안내와 동료 피드백의 구체적인 언어로 드러냅니다. AI 학습은 도구 사용과 함께 결과를 이해하고 판단하는 활동으로 설명합니다. 기존의 [학습법](https://codesquad.kr/learning-method/)과 [Olive 소개](https://codesquad.kr/olive/)를 바탕으로 한 브랜드 해석입니다.

| 키워드 | 실제 콘텐츠 | 인터랙션·그래픽 번역 | 증거 기준 |
| --- | --- | --- | --- |
| 융합 | 사람의 경험 + 개발 기본기 + AI 활용 | 둥근 사람 모듈, 중괄호 모듈, 겹친 원 모듈이 한 그리드를 구성. 학습 예시 안에서도 세 요소 연결 | 새로운 콘셉트 그래픽; 회사 성과로 표현하지 않음 |
| 화합 | 동료 리뷰 질문과 개선 이유 | ‘내 초안→동료 질문→수정 결과’ 비교. 색상 외 선택 라벨 표시 | 예시는 항상 ‘학습 예시’ 명시; 실제 댓글은 동의 후 사용 |
| 사회에 대한 공헌 | 개인의 배움이 현장 문제 해결과 지식 나눔으로 이어지는 방향 | ‘개인→동료→현장’ 흐름을 이야기와 사례 연결로 제안 | 검증된 활동만 사례화. 그 외에는 ‘지향합니다’ 사용 |
| AI 학습 | 문제 정의→AI 활용→결과 검증→동료 피드백→개선 | 회의록의 ‘제안’이 ‘확정’으로 잘못 요약된 예시를 비교 | 서비스의 자동 검증·자동 피드백 기능으로 오해하지 않게 표시 |

개인 학습자에게는 ‘나에게 맞는 시작점’, 기업 담당자에게는 ‘우리 팀의 과제와 적용 방식’, 대학·기관 담당자에게는 ‘교육 대상과 협력 목적’을 먼저 제시합니다. 전환 목표는 개인 과정 상세 진입과 조직별 문의 작성입니다. 검증 지표는 대상별 상세 클릭, 필터 후 상세 열기, 문의 메일 열기입니다. 메일 열기를 문의 제출 완료로 집계하지 않습니다. 개선 목표 수치는 실제 기준선 확보 후 정합니다.

## 3. 구별되는 디자인 방향 2개와 최종 추천

### A. 함께 만드는 배움의 작업실 — 최종 추천

큰 한국어 제목, 따뜻한 종이색 배경, 사람 중심 사진, 모양이 서로 다른 연결 모듈. 교육 과정은 비교하기 쉬운 가로 목록, 학습 방식은 작업 노트, 경험은 출처가 붙은 사례로 구성합니다. 사진은 실제 교육의 맥락을 보여주고, 초록은 선택과 주요 행동에 집중합니다. 메인 시안은 이 방향을 구현했습니다.

### B. 배움의 필드노트 — 대안

교육의 축적을 연구 기록처럼 읽는 편집 디자인. 첫 화면은 왼쪽 7열에 실제 프로젝트 결과물, 오른쪽 5열에 제목·담당 역할·출처. 다음 화면은 연도별 인덱스와 사례의 문제·실험·검증·회고를 교차 배치합니다. 배경과 작은 사진 캡션을 중심으로 사용하고, 연두색은 4px 인덱스 선과 CTA에 한정합니다. 대형 사진 1장, 옆 주석 1개, 수평 구분선이 기본 문법이며 연결 블록 그래픽은 사용하지 않습니다. 모바일은 결과물→한 줄 문제→사례 설명→CTA 순입니다.

| 비교 | A. 작업실 | B. 필드노트 |
| --- | --- | --- |
| 첫인상 | 열린 배움, 함께 시작하는 분위기 | 축적된 전문성, 검토 가능한 기록 |
| 첫 화면 비중 | 제목·행동 52% / 모듈·사진 48% | 프로젝트 결과물 58% / 주석·제목 42% |
| 탐색 문법 | 대상 선택 → 학습 체험 → 사례 | 대표 사례 → 연도·주제 인덱스 → 교육 |
| 주요 구성 | 목록, 작업 노트, 연결 도형, 인물 사진 | 편집 지면, 사례 사진, 연표, 옆 주석 |
| 준비 자료 | 기존 사진으로 시작; 촬영 보강 필요 | 고품질 프로젝트 결과·정확한 역할 자료가 선행 |
| 적합성 | 개인·기업·대학 세 대상을 균형 있게 안내 | 전문 담당자의 심층 검토와 B2B 사례집에 적합 |

**추천 이유:** 지금 확보된 자료는 교육 참여 이력과 학습 원칙이 중심입니다. A는 숫자나 결과물 자료를 과장하지 않아도 정체성과 다음 행동을 선명하게 전달합니다. B는 향후 사례 자료를 확보한 뒤 ‘교육 경험’ 상세의 편집 방향으로 활용할 수 있습니다.

## 8. 주요 인터랙션의 기본·선택·펼침 상태

학습 5단계의 공통 예시는 ‘도서 대출 상태를 알려주는 작은 웹 서비스’입니다. 문제 정의 노트 → 첫 구현 기록 → 동료 리뷰 메모 → 개선 전후 비교 → 회고와 적용 계획으로 결과물이 바뀝니다. 실제 학생 산출물로 오해할 수 있는 가짜 이름·수료 점수·고객 로고는 넣지 않습니다. 실제 결과물 참고 자료는 [2023 마스터즈 MAX 이슈 트래커](https://github.com/codesquad-members-2023/issue-tracker-max)입니다. 공개된 프로젝트의 존재와, 새로 기획한 5단계 활동 예시를 구분합니다.

AI 예시는 개인정보 없는 가상 회의록을 요약하는 상황입니다. AI 초안의 ‘금요일 배포 확정’ 표현에 동료가 근거를 묻고, 원문의 ‘제안’으로 수정하는 흐름입니다. 이는 제안하는 학습 표현이며 Olive의 실제 미션 및 자동 피드백 기능으로 단정하지 않습니다.

### 제작 및 검증 범위

기존 앱과 별도로 public/design-proposal에 시안을 추가했습니다. 접근성 상태는 실제 HTML 버튼·선택·펼침 요소로 구현했습니다. 시안의 모든 외부 링크는 조사에서 확인한 공식 소개·참가자 원문·대표 메일 경로입니다. 실제 문의를 발송하거나 유료 신청을 실행하지 않았습니다.

검증 결과는 [검증 기록](verification.html)에 별도로 제공합니다. 홈페이지 전체 개편의 사용자 테스트·스크린리더 실기 검증·실제 모집 데이터 연동은 후속 구현 범위입니다.
